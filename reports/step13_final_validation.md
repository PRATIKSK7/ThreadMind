The `human_*_1_to_5` columns in `reports/human_scoring_subset.csv` currently contain scores generated by an automated Independent LLM Scorer (Llama 3.2), NOT by a human.

**Does the assignment explicitly require human annotations?**

Based on the project README and `reports/brand_selection.md`, the assignment requires:
- ✅ An evaluation harness (completed)
- ✅ Explicit failure analysis (completed)
- ✅ Comparison against baselines (completed)

The assignment does not appear to explicitly mandate human annotations as a hard requirement. However, **the absence of human evaluation is a significant methodological limitation** that should be transparently disclosed:

> [!IMPORTANT]
> **What remains to be done for genuine human validation:**
> 1. A human annotator reads each of the 30 `conversation_history` + `agent_reply` pairs

> 4. Re-runs the agreement calculation script to compute genuine Judge-vs-Human Cohen's Kappa

## 5. Limitations

1. **No human evaluation.** All quality scores are automated. The LLM Judge-vs-Independent Scorer Kappa is poor-to-slight, and we cannot establish Judge-vs-Human agreement without actual human labels.

2. **Dense Retrieval Recall@K is unmeasured.** The 65.31% figure previously cited was incorrectly attributed. The actual Dense FAISS Recall@K has never been computed and recorded.

3. **High fallback rate (69.2%).** Most real-world conversations fall through to the expensive LLM path on unseen data.

4. **Hallucination rate likely underestimated.** The Judge missed clear hallucinations that the stricter scorer caught.

5. **Same-model bias.** Both automated evaluators are Llama 3.2, sharing blind spots.

6. **Language mismatch.** Non-English inputs receive English replies.

## 6. Deployment Recommendation

**The architecture is functionally complete.** All pipeline stages — thread reconstruction, intent classification, retrieval, reply generation, escalation, and automated evaluation — are implemented and tested.

**The system is NOT production-ready** due to:
- Unmeasured Dense Retrieval Recall@K
- 69.2% real-world fallback rate
- 4.59%+ hallucination rate
- No genuine human evaluation
- Unreliable automated quality gate (negative Kappa on 2 of 4 dimensions)

- ✅ Rigorous evaluation methodology (baselines, ablations, failure analysis)
- ✅ Honest reporting of limitations and failure modes
- ✅ Complete pipeline from raw data to grounded reply generation
- ✅ Leak-free evaluation design
- ✅ 100% local/free inference
- ⚠️ Missing: measured Dense Retrieval Recall@K (Step 14 will address this)
- ⚠️ Missing: genuine human quality evaluation
