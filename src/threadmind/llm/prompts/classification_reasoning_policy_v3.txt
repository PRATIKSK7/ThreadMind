# Decision Framework (CRITICAL REASONING SEQUENCE)
You must follow this exact sequence to determine the intent:
1. Understand the user's actual problem: What is the core issue being expressed?
2. Identify the operational object/entity involved: Is this about a physical package, a digital service, a locker, a billing charge, or an account login?
3. Identify the requested action/problem: Is the item missing, damaged, delayed, or are they asking for a refund?
4. Determine the strongest intent-defining evidence: Look at the actual conversational text, not just single keywords. 
5. Compare only plausible candidate intents: Eliminate intents that clearly do not match the object or problem.
6. Use retrieved examples as supporting evidence, NOT as ground truth:
   a. If the retrieved examples unanimously share an intent that aligns with the user's actual problem, prefer it.
   b. If retrieved examples conflict, resolve the conflict using the taxonomy boundaries below.
   c. If retrieved examples do not match the user's actual problem, ignore them and use taxonomy reasoning independently.
7. Prefer the candidate whose taxonomy definition best matches the user's actual problem.
8. Do not choose an intent merely because it appears frequently in retrieval if the taxonomy definition does not fit.
9. Do not let superficial lexical overlap override the actual intent (e.g., "wrong" does not automatically mean delivery_wrong_item).

# Taxonomy Boundary Disambiguation
When resolving conflicts or ambiguous text, apply these strict boundary rules:
- `account_access` vs `delivery_wrong_item` vs `delivery_missing` vs `delivery_delayed`: If the user explicitly mentions a problem with their physical order (wrong item, didn't arrive, delayed), it is a delivery issue, not `account_access`. "I am locked out of my account" is `account_access`.
- `amazon_locker` vs `delivery_missing`: If the locker door opened and was empty, or the package was stolen from a locker, the intent is `delivery_missing`. `amazon_locker` is strictly for technical failures with the locker itself (won't open, code invalid, location issues).
- `grocery_fresh` vs `returns_refunds`: If the problem is about spoiled food, missing groceries, or an Amazon Fresh order, prioritize `grocery_fresh`, even if the customer ultimately wants a refund for the spoiled food.
- `account_billing` vs `grocery_fresh`: If the core issue is about a charge or billing error on an Amazon Fresh order, use `grocery_fresh` if the context implies a grocery-specific fulfillment error. Use `account_billing` strictly for generalized Prime membership billing or unauthorized financial fraud.
